# 汽车改装合规通行证

本仓库记录该项目已确认的领域对象、事件名称和基础校验方式，便于不同系统交换一致的数据；并提供"部件认证暂停后的按用途精确影响处置"参考实现。

## 资料范围

- `contracts/domain.schema.json`：领域事件信封、聚合类型与事件名称。
- `data/sample.json`：一条用于本地联调的中文样例。
- `src/`：
  - `events.py` / `validator.py`：事件定义与信封校验。
  - `store.py`：仅追加事件存储（每聚合乐观并发、全局 event_id 幂等、跨聚合原子写）。
  - `domain.py`：把事件流重放成车辆、部件认证、案卷、申诉、检测证据、进程时钟等状态。
  - `service.py`：影响处置服务（圈定 → 技术确认 → 合规处置 → 复检/换件 → 另一人恢复）。
  - `projections.py`：从通行证、车辆（VIN）、部件序列任一入口重建同一条追溯链路。
- `tests/`：信封约定测试与全链路场景测试（含并发复核与部分恢复）。

当前资料覆盖车型配置、部件认证和施工履历。记录一经接收，标识、发生时间与版本不得原地改写；更正使用新的后继记录。个人、机构及商业敏感信息仅向履行职责所需的调用方开放。

## 处置规则要点

- **按证书用途精确生效**：暂停声明绑定批次集合与用途集合；圈定沿部件序列（绑定/在岗）与施工履历进行，同车型不同批次、不同用途不纳入；车辆按未施工、待检测、已取得通行证、已转卖分别标注。
- **先圈定后确认再处置**：技术人员确认匹配规则（可排除候选），合规人员只能对已确认目标决定暂停/复检/换件，范围不可外扩。
- **申诉只暂缓行政结论**：安全限制在申诉停留期间持续有效。
- **双人恢复**：换件/复检完成后，恢复人必须区别于处置决定人、复检签署人和换件施工人，且依据处置之后形成的新检测合格结果；换件恢复必须基于新件检测。
- **所有权转移**：当前通知送达新车主；历任车主区间、原施工方与部件履历完整保留，安全限制随车不随交易消失。
- **离线回传**：相同报告编号 + 相同内容指纹只接受一次；编号相同而内容变化时新旧证据并存，并另立独立争议，绝不覆盖先前证据。
- **期限延续**：整改与升级期限锚定原截止点，进程暂停/恢复不重新计时。
- **一致查询**：通行证、车辆、部件三入口解析到同一案卷集合，经同一投影输出一致的认证变更、施工、检测、申诉、换件、恢复链路。

## 本地检查

```bash
python3 -m unittest discover -s tests
```

## 测试与构建

测试命令：

```bash
python3 -m unittest discover -s tests
```

编译或构建命令：

```bash
python3 -m compileall -q src tests
```

这些命令可在单个 Linux 应用容器内执行，不需要另行启动外部服务。
