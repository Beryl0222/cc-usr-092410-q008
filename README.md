# 汽车改装合规通行证

本仓库记录该项目已确认的领域对象、事件名称和基础校验方式，便于不同系统交换一致的数据。当前版本在车型配置、部件认证和施工履历基线之上，实现了**认证暂停影响冻结服务**。

## 资料范围

- `contracts/domain.schema.json`：领域事件信封、聚合类型与事件名称。
- `data/sample.json`：一条用于本地联调的中文样例。
- `src/events.py`：事件目录（事件类型 → 聚合类型与必填载荷）。
- `src/validator.py`：事件信封与事件载荷的最小校验代码。
- `src/store.py`：仅追加事件存储，按聚合做乐观并发版本控制，支持幂等键。
- `src/projection.py`：把事件流折叠为当前状态与责任时间线的读模型。
- `src/freeze.py`：认证暂停影响冻结领域服务。
- `src/trace.py`：通行证 / 车辆 / 部件三入口统一链路查询。
- `tests/`：十个场景的完整测试。

记录一经接收，标识、发生时间与版本不得原地改写；更正使用新的后继记录。个人、机构及商业敏感信息仅向履行职责所需的调用方开放。

## 处置规则

认证被暂停时不按车型一刀切，而是沿「部件认证 → 序列号 → 绑定/施工记录」圈定车辆，并按被暂停的证书用途（`cert_use`）精确过滤：

| 环节 | 规则 |
| --- | --- |
| 圈定 | 同车型但使用其他批次/认证的车辆不入范围；车辆区分未施工、待检测、已取得通行证、已转卖四种状态 |
| 确认 | 技术人员先确认部件序列与施工匹配规则（范围哈希锁定，扩缩均拒绝） |
| 处置 | 合规人员在确认之后逐车选择暂停通行证、复检、换件或封存；确认人与决定人不得为同一人；处置必须恰好覆盖圈定范围 |
| 恢复 | 换件/复检完成后，由经办人之外的另一人依据暂停后新作出的合格检测恢复；检测机构本人不得恢复；支持逐车部分恢复，范围永不扩大 |
| 申诉 | 只暂缓行政结论；通行证安全限制在客观整改完成前持续有效 |
| 所有权 | 过户只追加责任时间线（原施工方、历任车主均保留）；当前通知转送给新车主 |
| 离线回传 | 相同编号 + 相同内容只接受一次；相同编号内容变化形成独立争议，先前证据不被覆盖，裁决只能在两个留证版本间选择 |
| 期限 | 整改期限与升级通知锚定证书暂停时的原截止点；进程暂停/恢复不重新计时，恢复后按原排程补投 |
| 查询 | 通行证、车辆、部件任一入口折叠同一条事件流，得到一致的认证变更、施工、检测、申诉、换件与恢复链路 |
| 并发 | 处置写入携带读取版本；两名合规人员并发复核时，持过期版本的一方冲突并整批回滚，重新读取后再决策 |

## 本地检查

```bash
python3 -m unittest discover -s tests
python3 -m compileall -q src tests
```

这些命令可在单个 Linux 应用容器内执行，不需要另行启动外部服务。
